## 二、建议新增的项（基线没有，smarthome 需要）

### 2.1 网络（TCP 回环，协议层/sim 轨用）

基线 **完全没开网络栈**（230 行中无任何 `CONFIG_NET` 行；`CONFIG_NSH_DISABLE_IFCONFIG=y`
也印证了这一点）。PC 模拟器走 TCP 回环或 UART 替身（联网硬件 no-go），若走
TCP 需新增（符号均已 grep 核实存在）：

| 新增项 | Kconfig 出处 |
|---|---|
| `CONFIG_NET=y` | `nuttx/net/Kconfig:40`（default n） |
| `CONFIG_NET_LOOPBACK=y` | `nuttx/net/Kconfig:200`（"Local loopback" 设备 lo，default n） |
| `CONFIG_NET_TCP=y` | `nuttx/net/tcp/Kconfig:8` |
| `CONFIG_NET_TCPBACKLOG=y`（listen 用） | `nuttx/net/tcp/Kconfig:306` |
| `CONFIG_NET_MAX_LISTENPORTS`（按需给值） | `nuttx/net/tcp/Kconfig:131` |
| socket 数/连接数如报不足再调 `NET_TCP_MAX_CONNS` 等 | `nuttx/net/tcp/Kconfig:73,89` |

同时建议解开 `CONFIG_NSH_DISABLE_IFCONFIG`（基线 =y，`apps/nshlib/Kconfig:434`），
演示时 `ifconfig lo` 可见回环口更直观。解除后 NSH 网络命令组可能牵连
`CONFIG_NETUTILS_NETLIB` 等，以 menuconfig 实际依赖为准——**待验证**。

cJSON：`CONFIG_NETUTILS_CJSON=y` 基线已开（:174，符号在
`apps/netutils/cjson/Kconfig:6`，无 NET 依赖、select LIBC_FLOATINGPOINT）。
引擎/存储按 `smarthome_storage.h` 约定刻意自研最小 JSON、不依赖它；sim 轨
若复用同一解析器，此配置纯属"保留无害"，不必依赖。

### 2.2 本应用开关

- `CONFIG_LVX_USE_DEMO_CONTEST2026_000_HELLO_APP=y`：定义在
  `app/hello_app/Kconfig`（映射为 `packages/demos/contest2026_421_hello_app`），
  `app/hello_app/Makefile`/`Make.defs` 以该符号作为构建开关。defconfig 必须置 y。
  **待验证**：该 Kconfig 是否已被编译树（packages/demos 层）source 进菜单树；
  若 menuconfig 里搜不到，需补 linkfile/manifest 层对接。
- 替换官方 demo：关 `CONFIG_EXAMPLES_LVGLDEMO`（见第三节），避免 LVGL demo
  与 smarthome 抢屏/抢栈（其 STACKSIZE 327680 = 320KB，:108）。

### 2.3 UART 传输（可选，若演示走 UART 替身）

- 契约 `smarthome_internal.h`：`sm_net_start_uart("/dev/ttyS1", 115200)`。
- 可用开关：`CONFIG_AIC_USING_UART0..3` 定义于
  `vendor/artinchip/chips/artinchips/Kconfig:24–36`；基线仅
  `CONFIG_AIC_USING_UART1=y` (:43)。如需第二路串口，开 `CONFIG_AIC_USING_UART2`
  并确认引脚复用（demo68-nor 板 pinmux）——**待验证** UARTx 与 /dev/ttySx 的
  对应关系以及引脚是否与屏/触摸冲突。

## 四、队伍仓板级配置可行性（board/contest_board）

现状（工作区实查）：

- `board/contest_board/` 自述"仅为占位骨架，不保证可启动"（board/contest_board/README.md），
  映射 `vendor/openvela/boards/contest2026_421_board`
  （manifest `contest2026_421_laoshuxiwantou.xml:14` linkfile）。
- 内容仅：`Kconfig`（定义 `ARCH_BOARD_CONTEST2026_000_BOARD` 占位符号）、
  `configs/nsh/defconfig`（一行占位 `CONFIG_ARCH_BOARD_CONTEST2026_000_BOARD=y`）、
  `src/board_boot.c`、`CMakeLists.txt`。
- 而 demo68-nor 能跑起来的板级层在
  `vendor/artinchip/boards/d12x/demo68-nor/`（pinmux/audio/display/sdmc 等
  src/ 全在里面），芯片层经 `CONFIG_ARCH_CHIP_CUSTOM_DIR="../vendor/artinchip/chips/artinchips"`
  （基线 defconfig:56）对接。

结论：

1. 队伍仓 contest_board 要真正替代 artinchip 板级层，需要补齐 pinmux、
   显示/audio/SDMC 初始化、mount 表等一整套 board 源码（即把
   `demo68-nor/src` 的能力搬/链过来），并处理 `ARCH_CHIP_CUSTOM_DIR` 与
   `ARCH_BOARD_CUSTOM_DIR` 的相对路径关系——不是一天能完成的事。
2. **短期建议**：编译直接用 artinchip 官方配置目录
   `vendor/artinchip/boards/d12x/demo68-nor/configs/`（基线 nsh_lvgl 或在其
   基础上 menuconfig 生成 smarthome 配置后 savedefconfig 回存队伍仓），
   contest_board 保留占位与说明，README 如实写"板级配置复用 artinchip
   demo68-nor 官方层，队伍仓板级目录为后续上游化预留"。
3. defconfig 落地建议：以本笔记第一~三节为操作清单，改完
   `make savedefconfig`（构建树内）再回存，避免手写 defconfig 与实际依赖漂移。
